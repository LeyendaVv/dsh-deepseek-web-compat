# 踩坑记录

每条都是实测踩过的，写清"现象 → 根因 → 处理"，方便下次直接对号入座。

## 1. 补丁在重启后消失

**现象**：改完 `node_modules/.../lib/index.js`，重启后补丁全没了。
**根因**：DSH 启动时会重装/重链 profile 依赖，npm 版本被从 store 重新落盘覆盖。
**处理**：把插件复制到稳定目录，profile 依赖改成 `file:` 指向它（`dsh plugin --profile <p> add file:<dir>`），之后重启不再被洗。**或者**每次重启后重跑 `patch-all.mjs`。

## 2. 崩溃的真凶不是"协议坏了"，是未处理的 Promise 拒绝

**现象**：`fatal load failure: DeepSeekWebError ... code: 'DEEPSEEK_WEB_PROTOCOL'`，整个应用退出。
**根因**：适配器在 `stream()` 里**提前发起** `powHeaderPromise`，若它先失败而没人 await，Node 24 默认把未处理拒绝当致命错误。
**处理**：给这类 fire-and-forget 的 promise 挂 `.catch(() => {})`（补丁 A3/B1）。同时把错误按业务码分类，避免误触发重建重试。

## 3. curl 通、插件不通 —— UA 的差别

**现象**：同一台机器，`curl` 拿 429 + HTML，浏览器却正常。
**根因**：WAF 按 UA 拦。默认 `curl/x.y` 直接被挡，还带 `Server: CW`、`Block-Event-Id`。
**处理**：诊断脚本一律带浏览器 UA（`DSWEB_UA` 可覆盖）。判定时先看是不是 HTML，别急着说"接口改了"。

## 4. token 看起来还在，其实早被服务端轮换了

**现象**：凭据库里明明有 token，却时不时要求重新登录。
**根因**：`GET /api/v0/users/current` 的响应里会带**新 token**（`data.biz_data.token`），插件只取 `id`，把新 token 丢了。
**处理**：补丁 A2/B3 —— `currentUser` 把新 token 带出来，适配器发现变化就 `storeCredential()` 写回。

## 5. DeepThink 开着时"只思考不回答"

**现象**：界面显示"已完成 35 秒"，消息区空白。
**根因**：模型把内容全放进思考通道，回答通道为空。
**处理**：补丁 B6（自动关思考重试一次）。临时可在配置里设 `thinking: disabled`。

## 6. 长产物被截断，看起来像"模型画错了"

**现象**：生成的 HTML 少了鹈鹕/少了自行车，检查发现没有 `</html>`。
**根因**：网页版单次回复约 **1 万字符**封顶。加长提示词只会让它想更久、输出更长，更容易撞上限——实测把思考量从 3.5 万涨到 5.8 万后，两版都截断。
**处理**：补丁 B5 的质量前言（先骨架、分块补、标 `<DSH_CONTINUE/>`）+ `check-artifact.mjs` 做机械验收。

## 7. 工具调用被静默丢弃

**现象**：模型"说了要写文件"，但没有任何 `tool/call`。
**根因**：它发的是 DSML 变体（全角竖线 `｜｜`、参数里再套 `name`），插件解析器要求规范写法。
**处理**：补丁 B4 归一化，把变体转成 `<dsh_tool_calls>` JSON。

## 8. 设置页显示未登录，但模型能用

**现象**：面板/设置页显示未登录，重新登录后又反复。
**根因**：内嵌网页面板用内存分区，重启即清空；宿主凭据仍在。
**处理**：以 `diag.mjs live` 的结果为准，界面状态只作参考。

## 9. 不要把网页版设成唯一模型

接口是私有的，改版是迟早的事。一旦它挂了，最坏后果应是"这条车道报错"，而不是"应用起不来"。所以：默认模型保留一条正常车道（官方 API / 其它 provider），网页版按需切换。
