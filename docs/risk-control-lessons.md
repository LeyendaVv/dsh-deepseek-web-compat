# 私有网页接口爬虫：约束与教训

> 来源：一次真实事件——把 DeepSeek 网页版（chat.deepseek.com）接成 DSH 模型车道，约 6 小时后账号被禁言 3 天。
> 目的：记录"爬虫/反爬"这条路线上哪些是硬约束、哪些只是提高成本，以及我们踩过的坑。
> 标注：「实测」= 有日志/数据支撑；「推断」= 经验判断。

---

## 一、三道门，不是三道可选项

要调通一个私有网页接口，缺一不可：

| 门 | 本质 | 缺失后果（实测） |
|---|---|---|
| **身份凭证**（token） | 你是谁 | `40003 Authorization Failed` |
| **客户端指纹**（请求头） | 你是不是官方客户端 | WAF 拦截：429 + HTML 页（`Server: CW`） |
| **准入成本**（PoW 等） | 你愿不愿意付算力 | 挑战不通过 / 被拒 |

教训：**先搞清"要什么"，再动手试。** 我们一开始不知道链路长什么样，靠反复试错，虽然最后跑通，但期间产生了大量失败请求——这些都是可见的异常样本。

---

## 二、检测面模型（这次被封后总结）

风控识别的是**行为分布**，不是单条请求。按可疑度排序：

| 层级 | 我们的具体表现（实测） | 为什么可疑 |
|---|---|---|
| **内容** | prompt 是固定 XML 模板 + 50 个工具 JSON Schema | 一次命中即可定性，成本最低 |
| **行为** | 10 轮 239 秒、单轮 537 秒；定时任务每 30 分钟；全天候 | 无人类作息、无浏览行为、间隔由程序常数决定 |
| **关联** | 面板 + 浏览器 + keeper + 脚本，同一 token 多端共享、反复轮换 | 会话异常共享是风控标配规则 |
| **计算** | PoW 求解恒定 60–90ms、nonce 分布集中 | 统计上像同一台机器循环 |
| **网络** | 固定 UA、固定请求头组合、固定顺序 | 真实浏览器会随版本/语言/扩展变化 |

**关键结论：单层伪装都能做到，难的是让五层同时"像人"，而其中"内容层"在需要工具调用时根本无法拟人化。**

---

## 三、硬约束（这些没法绕过）

### 1. 工具调用与"拟人化"互斥

要让模型结构化输出工具调用，就必须在 prompt 里放契约与 schema。人不会这么说话。
→ 想拟人化，只能退化成纯问答；纯问答又不需要接程序。

### 2. 量级骗不过统计

单请求可以做到天衣无缝，但一天上千次请求的间隔分布、时段分布一定与人类不同。
→ 要把量压到人类水平，就失去了自动化意义。

### 3. 成本收益不对称

- 对方：一次判定失败（漏判）几乎无成本，规则可以随时更新、可以事后追溯
- 我们：任何一次被判定 → 账号处罚
→ 这是"赌概率"，不是"解技术题"。

### 4. 判定可追溯

今天没被封，不代表下个月不封。历史请求都在对方日志里。

## 四、真正能降低风险的做法（如果仍要做）

按性价比排序：

1. **单一客户端、单一 token 来源**——不要多端共享、不要定时抓取轮换
2. **硬性预算**：每小时 N 次、每天 M 次，超了停
3. **节奏加噪声**：随机间隔、作息曲线、夜间停
4. **真实浏览行为**：切页、看历史、偶尔不发
5. **内容自然化**：只在需要工具时用契约，其余用自然语言
6. **可观测**：每小时请求数、失败率、成功率曲线；异常自动熔断

> 即使六条全做，也只是"更难被发现"，不是"安全"。

## 五、方法论教训（可迁移到任何爬虫项目）

### 教训 1：先观测，再优化

我们只有"失败后"的日志（`pow-error.log`、`repair.log`），从来没有"行为指标"（频率、间隔、成功率随时间）。
→ **下次任何爬虫项目，第一天就把频率/间隔/失败率画成曲线**。能被看见的风险才可能被管住。

### 教训 2：风险提示 ≠ 风险控制

我在评估里写了"有封号风险"，但没有设任何硬性停止条件。
→ **没有闸门的提醒是装饰**。每个自动化都必须带：预算、熔断、一键停止。

### 教训 3：验证脚本不要升级成常驻服务

一次性验证是对的；把验证脚本改成定时任务（keeper 每 30 分钟抓 token），性质就从"实验"变成"持续对抗"。
→ 验证完就拆，别留着常驻。

### 教训 4：能力提升会加速撞线

我们每修好一个 bug（崩溃、空白、工具调用），使用强度就上一个台阶。
→ 修得越通，越要主动限流。

### 教训 5：区分"借来的路"和"自己的资产"

私有接口上盖的房子，今天能住，明天可能就拆。长期价值在于：
- 协议文档
- 诊断方法
- 复现步骤

这些可以迁移；接口本身不行。

## 六、事件时间线（实测）

| 时间 | 事件 |
|---|---|
| 15:25 | 网页登录拿到 token，约 66 分钟后失效 |
| 16:31–16:34 | 连续 40003，触发重试风暴 |
| 17:14 | 再次失效 |
| 19:53 | 再次失效；期间有 10 轮自动化任务（239s / 24 次工具调用） |
| 20:41 | 从浏览器抓到新 token（15 分钟有效期的 JWT 是另一家，不是这里） |
| 20:44 | 账号显示：**禁言至 2026-11-11 19:51** |
| 20:47 | 停用网页车道、杀掉常驻进程、默认模型切回官方 API |

---

## 七、一句话结论

> **token 解决"能不能进"，人类噪声只解决"多久被发现"，解决不了"会不会被发现"。**

想长期稳定使用，唯一正解是官方 API；私有接口只适合做一次性的协议学习，学完即拆。
